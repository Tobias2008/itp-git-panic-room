# Ordnet die folgenden Commit-Messages zu. (Gut oder schlecht?). 
## Begründe mindestens drei deiner Entscheidungen. 

### Gute Commit-Messages:
Add login validation,
Refactor Calculator for readability,
Remove unused imports,
Add null check,
Rename variables -- man weiß was passiert ist,
Improve readability,
Handle edge cases,

### Schlechte Commit-Messages:
Update,
Fix bug,
stuff -- Was soll ich mir darunter vorstellen - da weiß niemand was hier passiert,
Changes in app,
Fix issue #23,
Refactor code,
Cleanup -- man weiß zwar das etwas gecleaned wird - aber was genau,
Small fixes,
Temporary fix,

### Grenzfälle 

final version, 
- man kann sich ungefähr denken, was passiert und man weiß das jetzt alles fertig ist, aber es ist doch unklar, weil was genau ist jetzt geändert wurde
- was geändert wurde...
- wenn man nichts geändert hat, und das einfach als Ende des Projekts macht
- 'nothing Changed, FINAL VERSION' oder '...changes..., FINAL VERSION'

Update Calculator,
- es ist sehr breit gebunden, es kann ja alles irgendwie geändert worden sein
- was genau gemacht wurde...
- wenn das Projekt sehr viele sachen einbindet, und der Calculator nur ein kleines nebenfeature ist
- 'Updated calculation logic in function ...' 

Improve performance,
- die Performance wird besser, ergibt sinn, aber was wurde geänder dass die Performance besser wird 
- was geändert wurde...
- wenn sich nur eine sache geändert hat (?)
- 'improve performance ...' - mit ... als sache, die geändert wurde

Adjust logic,
- die Logik wurde geändert, aber von wo/was/wie
- was/wo/wer/wie/warum wurde was geändert 
- wenn es nur eine Logik gibt, die man ändern könnte
- 'Adjust logic in ...'
